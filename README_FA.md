# AEGISVISION v1.5.0 — Live Camera Intelligence

این نسخه قابلیت اتصال دوربین‌های شبکه RTSP/RTSPS و اجرای تحلیل هوشمند زنده را به پروژه AEGISVISION اضافه می‌کند. قابلیت‌های قبلی پروژه شامل Automatic Video Analysis، تشخیص اشیا، SORT، خروجی ویدئوی Annotated، Event Detection و SOC حفظ شده‌اند.

## قابلیت‌های این نسخه

- ثبت دوربین RTSP و RTSPS در سطح سازمان.
- ذخیره نام کاربری و رمز عبور دوربین به‌صورت رمزنگاری‌شده با کلیدی مشتق‌شده از `SECRET_KEY` جنگو.
- عدم بازگرداندن آدرس Stream و اطلاعات ورود در پاسخ API دوربین.
- آزمون اتصال به دوربین و دریافت یک فریم قبل از شروع تحلیل.
- Worker پس‌زمینه مستقل که با `Start_AEGISVISION.bat` اجرا می‌شود.
- دریافت فریم RTSP، تشخیص اشیا با مدل موجود Faster R-CNN MobileNetV3 و رهگیری با SORT.
- رسم Bounding Box، کلاس شیء، Confidence و Track ID روی تصویر زنده.
- اجرای قوانین Zone Intrusion، Line Crossing و Loitering برای دوربین زنده.
- ذخیره Eventها در دیتابیس و نمایش هشدارها در صفحه Live Camera.
- وضعیت Worker، Heartbeat، سلامت جریان، FPS تحلیل، وضوح تصویر و شمارنده فریم‌ها.
- رابط فارسی/انگلیسی با پشتیبانی از RTL/LTR.

## نصب روی ویندوز

### ۱. پشتیبان‌گیری

اگر این بسته را روی پروژه موجود نصب می‌کنی، ابتدا از دیتابیس، رسانه‌ها و فایل `.env` نسخه پشتیبان بگیر. این بسته برای انتشار سورس در GitHub آماده شده و عمداً شامل دیتابیس و فایل‌های رسانه‌ای محلی نیست.

- `backend/db.sqlite3` — دیتابیس محلی و اطلاعات کاربران.
- `backend/media/` — ویدئوها، فریم‌ها و خروجی‌های تولیدشده.
- `.env` — کلیدها و تنظیمات محرمانه.

این داده‌ها را از پروژه فعلی خودت جداگانه نگه دار و روی آن‌ها فایل خالی یا نمونه کپی نکن.

### ۲. آماده‌سازی تنظیمات محیط

از فایل `.env.example` در ریشه پروژه یک فایل `.env` بساز. دستور زیر را دو مرتبه اجرا کن و دو مقدار متفاوت را به‌ترتیب در `DJANGO_SECRET_KEY` و `JWT_SIGNING_KEY` قرار بده. بدون تنظیم این دو کلید برنامه اجرا نمی‌شود. فایل `.env` را در GitHub آپلود نکن.

```cmd
copy .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

## راه‌اندازی اولین دوربین

### ۱. اطلاعات موردنیاز

برای هر دوربین باید این موارد را داشته باشی:

- آدرس IP یا نام میزبان دوربین/NVR که از رایانه اجرای AEGISVISION قابل دسترس باشد.
- پورت RTSP (معمولاً 554، اما مقدار واقعی را از تنظیمات دوربین بگیر).
- مسیر دقیق Stream از سازنده دوربین.
- نام کاربری و رمز عبور مجاز برای مشاهده جریان.
- دسترسی شبکه و مجازبودن RTSP در تنظیمات دوربین و Firewall.

نمونه‌های ساختاری صرفاً راهنما هستند و لزوماً برای مدل دوربین تو معتبر نیستند:

```text
rtsp://192.168.1.50:554/stream1
rtsp://192.168.1.50:554/cam/realmonitor?channel=1&subtype=0
rtsps://192.168.1.50:322/stream1
```

نام کاربری و رمز عبور را در URL ننویس. آن‌ها را در فیلدهای جداگانه فرم دوربین وارد کن. Queryهای معمول انتخاب Stream پشتیبانی می‌شوند، اما از قراردادن Token یا رازهای حساس در Query خودداری کن.

### ۲. ثبت دوربین

1. وارد AEGISVISION شو.
2. سازمان موردنظر را انتخاب کن.
3. از منوی **Cameras / مدیریت دوربین‌ها** یک دوربین جدید ثبت کن.
4. نوع منبع را RTSP یا RTSPS انتخاب کن.
5. Stream URL، نام کاربری و رمز عبور را وارد کن.
6. نرخ تحلیل را ابتدا روی 1 یا 2 FPS قرار بده.
7. آستانه Confidence را ابتدا روی 0.55 قرار بده.
8. ذخیره کن.

### ۳. آزمون اتصال و شروع تحلیل

1. وارد صفحه **Live Camera Intelligence / هوشمندی زنده دوربین‌ها** شو.
2. دوربین را انتخاب کن.
3. روی **Test connection / آزمایش اتصال** بزن.
4. اگر آزمون موفق بود، روی **Start live / شروع پخش زنده** کلیک کن.
5. Worker به جریان وصل می‌شود و پس از دریافت فریم اول، تصویر حاشیه‌نویسی‌شده، Detectionها و Track IDها را نمایش می‌دهد.

اگر دوربین خاموش یا شبکه موقتاً قطع شود، Worker وضعیت Reconnecting را ثبت و با تأخیر افزایشی برای اتصال مجدد تلاش می‌کند. می‌توانی با Stop live پردازش همان دوربین را متوقف کنی.

## قوانین تحلیلی روی دوربین زنده

بعد از شروع جریان، در پنل Live analytics rules یک قانون بساز:

- **Zone Intrusion:** حداقل سه نقطه روی تصویر انتخاب کن تا Polygon محدوده ساخته شود.
- **Line Crossing:** دقیقاً دو نقطه برای خط مجازی انتخاب کن و جهت عبور را مشخص کن.
- **Loitering:** Polygon محدوده و حداقل زمان توقف را تعیین کن.

برچسب‌ها باید نام کلاس‌های COCO باشند؛ مثل `person`, `car`, `truck`, `bus`, `bicycle`. برای اعمال قانون روی همه کلاس‌ها، فیلد برچسب را خالی بگذار. قوانین فعال توسط Worker خوانده می‌شوند و Eventهای جدید در پنل هشدارهای زنده نمایش داده می‌شوند.

## تنظیمات عملکرد

- `target_fps`: سقف نرخ نمونه‌برداری و اجرای AI برای هر دوربین، بین 1 تا 10 FPS.
- `confidence_threshold`: آستانه اطمینان تشخیص.
- Device: در حال حاضر حالت `auto` انتخاب می‌شود؛ اگر CUDA در نصب PyTorch قابل استفاده باشد از GPU استفاده می‌شود، در غیر این صورت CPU.
- Worker در هر Process یک مدل تشخیص را به کمک cache نگه می‌دارد و اجرای inference چند دوربین را با قفل مشترک سریالی می‌کند تا از بارگذاری هم‌زمان مدل روی حافظه جلوگیری شود.

**پیشنهاد شروع:** ابتدا فقط یک دوربین را با 1–2 FPS و رزولوشن 720p یا پایین‌تر آزمایش کن. بعد از بررسی دما، CPU/GPU و نرخ واقعی پردازش، دوربین‌ها یا FPS را افزایش بده.

## محدودیت‌های فعلی — مهم

- در این نسخه منبع سمت سرور فقط RTSP/RTSPS است. گزینه Browser camera برای دریافت تصویر مرورگر به Worker RTSP متصل نیست و Live AI سمت سرور برای آن فعال نمی‌شود.
- پیش‌نمایش صفحه با JPEG snapshotهای تازه‌شده نمایش داده می‌شود؛ این WebRTC/HLS و پخش پیوسته 25/30 FPS نیست. نرخ نمایش به سرعت Worker و شبکه وابسته است.
- `target_fps` نرخ نمونه‌برداری AI است، نه تضمین FPS دوربین یا پخش مرورگر.
- ضبط پیوسته و آرشیو کامل ویدئوی RTSP در این نسخه پیاده‌سازی نشده است؛ این نسخه فریم حاشیه‌نویسی‌شده اخیر و Eventها را نشان می‌دهد.
- PTZ، حرکت دوربین، جابه‌جایی Track ID بین چند دوربین و Re-identification افراد پیاده‌سازی نشده‌اند.
- Track ID فقط در نشست جاری همان دوربین معتبر است و شناسه هویت واقعی افراد نیست.
- پشتیبانی چند دوربین از نظر ساختار وجود دارد، اما inference در یک Worker Manager مشترک سریالی شده است؛ ظرفیت عملی به سخت‌افزار بستگی دارد.

## امنیت و نگهداری

- نام کاربری و رمز عبور دوربین با Fernet رمزنگاری و در دیتابیس ذخیره می‌شوند؛ API آن‌ها را برنمی‌گرداند.
- برای رمزگشایی داده‌های قبلی باید همان `SECRET_KEY` زمان ذخیره رمزها حفظ شود. تغییر آن بدون انتقال کلید باعث می‌شود رمزهای ذخیره‌شده قابل رمزگشایی نباشند. اگر دیتابیس نسخه قبلی را نگه می‌داری، قبل از جایگزینی کلید باید برنامه انتقال و رمزنگاری مجدد اطلاعات دوربین انجام شود؛ این ZIP شامل دیتابیس قبلی نیست.
- تنظیمات Django از فایل `.env` در ریشه پروژه خوانده می‌شوند. برنامه بدون کلیدهای مستقل `DJANGO_SECRET_KEY` و `JWT_SIGNING_KEY` اجرا نمی‌شود. در استقرار واقعی `DJANGO_DEBUG=False`، `DJANGO_ALLOWED_HOSTS`، CORS، CSRF، HTTPS، Firewall و دسترسی شبکه را مطابق محیط امن پیکربندی کن. فایل `.env.example` فقط نمونه است و مقادیر واقعی نباید در Git قرار بگیرند.
- آدرس RTSP نباید در لاگ، اسکرین‌شات یا پیام عمومی قرار بگیرد؛ مخصوصاً وقتی شامل پارامترهای داخلی شبکه است.
- دوربین را فقط در شبکه و با مجوز مالک/سازمان متصل کن.

## عیب‌یابی

### Worker offline

- مطمئن شو فایل جدید `Start_AEGISVISION.bat` را اجرا کرده‌ای.
- گزارش `backend/logs/live_camera_worker.log` را باز کن.
- اگر Worker با پیام already running متوقف شده، پنجره Worker قبلی را ببند و Launcher را دوباره اجرا کن.

### RTSP connection failed

- از همان رایانه با VLC یا ابزار مورداعتماد دیگر آدرس Stream را آزمایش کن.
- IP، پورت، مسیر Stream، مجوز کاربر، Firewall و دسترسی LAN را بررسی کن.
- بعضی دوربین‌ها نیازمند فعال‌کردن RTSP یا ساخت حساب کاربری مخصوص مشاهده‌اند.
- در صورت استفاده از RTSPS مطمئن شو OpenCV/FFmpeg نصب‌شده از پروتکل و TLS دوربین پشتیبانی می‌کند.

### No live frame yet

- صبر کن تا Worker فریم اول را بخواند و مدل را بارگذاری کند؛ اولین اجرای مدل ممکن است وزن‌های COCO را دانلود کند.
- گزارش Worker را بررسی کن و از شروع چند دوربین هم‌زمان برای اولین بار خودداری کن.

### Migration error

```cmd
python manage.py showmigrations organizations
python manage.py migrate
python manage.py check
```

از حذف `db.sqlite3`، پاک‌کردن پوشه media یا اجرای `migrate --fake` خودداری کن.
